0现状诊断现状梳理 → 问题清单 → 重构目标

easy-tdx 是 FinFeed 的「通达信 / Mac / 扩展行情 / 巨潮 / 缠论 / 回测」统一数据查询工作台。当前实现为 Vue 3.4 单体视图 + 7 个子组件 + FastAPI 异步任务后端，功能完整但交互与展示停留在「可用」层级，与项目 2.1.0 的现代 SaaS 设计语言（warm minimal、4pt grid、红涨绿跌）存在明显落差。

📐 当前架构（as-is）
EasyTdxView.vue→ StockPicker→ QuickTasks→ ParamForm→ ResultPanel→ TaskStatus
api/easytdx.js→ /api/easytdx/*（meta / run / task / tasks / download）
  • 模式切换：workbench / functions 两个页面级模式，互斥显示，导航与快捷任务不可共存。
  • 结果渲染：file / message / json / table 四类；table 纯平铺，json 走 KV 卡片。
  • 任务执行：800ms 轮询，状态 + 进度条 + 日志，固定 240px 常驻底部。

重构目标

可探索
导航、搜索、收藏、最近记忆融为一体，任意位置直达目标功能，消除模式割裂。
可交互
表格可排序 / 过滤 / 固定列 / 导出 / 行详情；拖拽分栏；纯鼠标直达。
有语义
红涨绿跌贯穿表格与 KPI；结果按类型选择最优可视化；状态反馈及时。
⚠ 边界约束
后端 API 契约（meta / strategies / run / task / tasks / download）保持兼容，本次为纯前端重构，后端仅做可选扩展（列级展示配置，见 §4.4）。

1布局重构信息架构 · 四区模型 · 响应式断点

核心思路：把「模式切换」改为「常驻三区 + 可折叠面板」。导航永远可见，参数面板按需展开，结果区始终主导，任务坞智能伸缩。消除页面级跳变，建立稳定的视觉框架。

2.3 关键行为下沉

  • 轮询逻辑移出视图：useTaskRunner.js 封装 submit → 800ms 轮询 → success/error 收敛 → 中止/超时（60s 无日志更新判定卡死，提示重试）。视图只消费 store.task。
  • 参数注入规则集中化：stock → params 的注入逻辑（hasCode / hasStocks 分支）从视图与任务组件中抽出为纯函数，供 selectFunc / runTask / run 三处复用。
  • 结果渲染注册表：resultTypes.js 以 (type, func.chart) 为键分发渲染器，新增结果类型只需注册，不改面板。
  • 格式化纯函数化：format.js 保持无副作用；新增 cellColor(value, col) 返回 CSS 类名（涨红跌绿），展示层消费。

3交互方式升级交互模式 · 状态矩阵 · 拖拽 · 反馈（纯鼠标）

交互设计原则：鼠标直达、状态可见、操作可撤销。本方案为纯鼠标操作设计——点击、悬停、拖拽、滚轮、右键、双击即可完成全部流程，不依赖任何键盘操作（键盘仅保留无障碍基础，见 §5.3，不作为操作路径）。所有可点击元素具备完整状态环（default → hover → active → selected → disabled），运行类操作一律给 loading 反馈与完成通知。

3.3 拖拽与手势规范

拖拽分栏（Workspace）
  • 分隔条 4px 热区，hover 变宽并显示双向箭头光标。
  • 拖动过程实时更新 ui.paneRatio，最小参数宽 280px，结果最小 420px。
  • 吸附点：参数 320px / 360px / 480px，接近 ±12px 自动吸附，松开后 140ms 缓动归位。
  • 双击分隔条复位 320px。
  • 窄桌面（<1024px）自动退化为抽屉模式，拖拽能力隐藏。
拖拽列（DataTable）
  • 列头拖拽到左侧图钉区（代码/名称列）→ 固定该列（sticky + 底色区分）。
  • 拖拽列头横向移动 → 调整列序（表头显示插入指示线）。
  • 收藏 Tab 内支持拖拽排序（Rail 项），用 HTML5 DnD 或 pointer 事件实现，含放置位指示。

3.5 反馈与通知

  • Toast：成功（执行完成 / 已收藏 / 已复制）、失败（提交失败 / 中止）、中性（已加入最近）。右上角堆叠，200ms spring 滑入，3.5s 自动消失，支持手动关闭。
  • 任务状态语义：空闲（灰）/ 排队（蓝）/ 执行中（品牌色 + 进度环 + 阶段文案）/ 成功（绿徽章 + toast）/ 失败（红徽章 + 错误详情 + 重试）/ 已中止（灰）。aria-live="polite" 播报状态变化。
  • 截断感知：结果超过展示上限时，工具条常驻「已截断 N 行」提示 + 一键导出完整数据（§4.3）。
  • 撤销：收藏误删可在 toast 内点击「撤销」恢复。

所有新样式严格消费既有 --ff-* 设计令牌（4pt 网格、10px 圆角基准、warm minimal 色板），不新增全局色值；图表使用 --ff-chart-* 十六进制值（canvas 无法解析 var）。

5.2 新增样式要点

  • 骨架屏：首载与功能切换时结果区显示表格骨架（--ff-skeleton-base 底 + 1600ms 流光），替代当前纯 spinner。
  • 进度环：RunBar 与 Dock 状态徽章使用环形进度（SVG stroke-dasharray），执行中显示百分比。
  • 粘性工具条：结果工具条与 CommandBar 使用 backdrop-filter: blur(8px) + 半透明表面色。
  • 表格样式升级：斑马纹（偶数行 --ff-bg-subtle 50% 透明度）、表头加粗 12px、固定列左侧阴影分隔线、行 hover 高亮。
  • 涨跌色卡片：KPI 卡底色使用 --ff-up-subtle / --ff-down-subtle，数值 24px tabular-nums。
  • 空态插画：SVG 线性图标 + 主行动按钮，替代纯文字。

5.3 主题与无障碍

  • 深浅主题：全部走令牌，暗色下自动反转（tokens.css 已定义 [data-theme=dark] 全套）；日志面板固定深底（现状保留，属数据终端惯例）。
  • reduced-motion：@media (prefers-reduced-motion: reduce) 关闭位移类动画，保留 opacity 过渡；tokens.css 已有 --ff-dur-fast: 0ms 钩子，追加全局覆盖。
  • 无障碍辅助（不构成操作依赖）：交互元素保留 :focus-visible 焦点环；Dock 状态区 aria-live="polite"；Rail 选中项 aria-current="true"；下拉 role=listbox + aria-selected。这些仅为读屏 / 无障碍服务，鼠标用户全程无感。

6实施步骤六个阶段 · 涉及文件 · 验收标准

按「先地基、后壳层、再交互、末打磨」推进。每阶段保持可运行、可回归；Phase 1 完成即为一次完整可用的布局切换。建议与设计走查并行：design-schemes/ 中 01-minimal-pro 与 03-private-wealth 的视觉语言与本方案一致。

  1. Phase 0 · 状态与逻辑下沉 2-3 天

    新建 stores/easytdx.js（stock / selectedFunc / task / ui）、composables/useTaskRunner.js（轮询 / 中止 / 超时）、composables/useRecentFunctions.js（收藏 / 最近 / 持久化）。将视图中的选股注入、轮询、最近任务逻辑迁移；format.js 增加 cellColor。

    涉及：＋5 个新文件；改 EasyTdxView.vue（瘦身）、format.js。

    验收：store 单测覆盖注入规则；视图 script 减少 ≥60%；页面行为与重构前完全一致。

  2. Phase 1 · 四区布局壳 3-4 天

    落地 CommandBar / Rail（含折叠、全部/收藏/最近 Tab、搜索）/ Workspace 分栏 / ActivityDock 折叠坞；删除双模式，导航常驻。响应式断点全部生效。

    涉及：＋EasyTdxCommandBar / EasyTdxRail / EasyTdxRailItem / EasyTdxWorkspace / EasyTdxActivityDock；改 EasyTdxView.vue 模板为四区组装、EasyTdxNav.vue 迁移进 Rail。

    验收：5 个断点截图对比无溢出；Rail 折叠动画流畅；无模式切换跳变。

  3. Phase 2 · 参数面板与执行流 2-3 天

    拆分 EasyTdxParamField（7 种类型）、EasyTdxRunBar（校验 / 中止 / 进度环）；参数面板可折叠、窄屏转抽屉。

    涉及：＋2 新文件；改 EasyTdxParamForm.vue、EasyTdxStockPicker.vue（悬停高亮 + 最近标的 + aria）。

    验收：无参功能直接显示执行按钮；必填校验有内联错误；点击执行按钮即可运行。

  4. Phase 3 · 结果渲染器重构 4-5 天

    按 §4.1 注册表拆出 ChartView / MetricCards / DataTable / KvView / ListView / FileView / MessageView + ResultToolbar；表格实现排序 / 过滤 / 固定列 / 虚拟滚动 / 行详情 / 导出；K线图表优先；回测 KPI 卡。

    涉及：＋6 新文件；改 EasyTdxResultPanel.vue 为分发骨架、format.js。

    验收：以 mac_stock_kline / backtest_run / mac_capital_flow / cninfo_announcements 四类真实数据回归，均命中预期渲染器；CSV 导出内容与表格一致。

  5. Phase 4 · 高级交互 2-3 天

    命令面板（CommandBar 搜索框按钮唤起）、收藏拖拽排序、拖拽分栏、Toast 通知（含撤销）、聚焦模式。

    涉及：＋EasyTdxCommandPalette.vue（可选）、Toast 复用全局或模块内实现；改 RunBar / Rail / Workspace。

    验收：§3.2 鼠标操作表逐条可操作；拖拽无跳动；刷新后收藏与最近保留。

  6. Phase 5 · 打磨与回归 2 天

    骨架屏、空态、错误态统一；reduced-motion、aria 审计；深浅主题走查；性能核对（虚拟滚动、轮询清理）。

    涉及：样式与 a11y 收尾；web/src/styles/ 如有必要补 1-2 个通用类。

    验收：Lighthouse a11y ≥ 95；onBeforeUnmount 无泄漏轮询；暗色主题截图无死色。

实施建议

  • 顺序不可逆：Phase 0 先行，否则后续组件拿不到统一状态源。
  • 每阶段独立提交：commit message 前缀 refactor(easytdx): phase-N …，便于回滚定位。
  • 后端零改动：除非启用 §4.5 可选扩展，本次无需触碰 finfeed/integrations/easytdx/。
  • 真实数据回归：复用 scripts/ 中现有数据抓取脚本造数，避免用 mock 验证渲染器。

7风险与验收兼容性 · 风险清单 · 验收矩阵

7.1 兼容性约束

  • API 契约冻结：meta / strategies / run / task / tasks / download 响应结构不变，前端解析层只读不改。
  • 红涨绿跌：所有新增着色遵循 A 股惯例（--ff-up 红 = 涨，--ff-down 绿 = 跌），与现有 K线图、任务状态一致。
  • 路由与侧栏：/easytdx 路由与 Sidebar 入口不变；web/src/api/easytdx.js 仅按需新增方法，不删除现有导出。
  • 持久化迁移：收藏/最近 key 带版本号，未来 schema 变更可无损迁移。
