方案总览 · EXECUTIVE SUMMARY

0. 方案摘要

将 AI 投研从「单页堆叠的功能面板」重构为「以任务与报告为中心的分析工作台」：配置下沉、阅读升级、任务可视化、对话带上下文。

① 结构分层

1 个入口页 + 4 个职能页（工作台 / 分析师 / 报告 / 任务），设置独立成区。普通用户与高级用户各取所需，互不干扰。

② 阅读升级

报告由 <pre> 纯文本升级为「结构化报告阅读器」：Markdown 渲染、结论摘要卡、数据表格、ECharts 图表、目录导航。

③ 任务可见

引入任务模型：排队 → 分阶段执行（采集/映射/成文）→ 完成/失败，全程进度可视化，可取消、可重试。

④ 对话带上下文

分析师工作区引入「上下文面板」：会话内 @ 标的、引用报告，右侧实时显示标的卡片与数据快照，减少记忆负担。

⑤ 状态体系完备

骨架屏 / 空状态 / 错误恢复 / 分阶段加载提示全覆盖；新手引导 + 快捷键 + 批量操作兼顾两类用户。

⑥ 渐进式落地

4 个阶段（约 6-8 周），每阶段独立可发布、可回滚，先结构后视觉再体验，风险可控。

核心设计原则：「分析是任务，报告是资产，对话是手段，配置是支撑」——四个词定义 AI 投研的全部信息，页面结构由此导出，而非把功能平铺在一个滚动页上。
现状诊断 · CODE AUDIT

1. 现状诊断

基于 web/src/views/AiView.vue（1,034 行）与全局布局（App.vue / Sidebar.vue）的代码审查，确认 8 项核心问题。

问题现状证据（源码）影响
① 单页堆叠状态卡、分析配置、Prompt 编辑、模型管理、对话、历史报告 6 类职责全部纵向堆叠于一个滚动页滚动路径长（>1000 行模板），核心操作「生成复盘」被压在报告卡右上角，认知负担重
② 配置与使用混层5 个 Prompt 编辑 textarea（map_system / map_user / …）直接平铺在页面上，与对话同级普通用户暴露 Prompt 工程细节；开发者配置与消费场景无区分，两种用户都体验受损
③ 报告纯文本报告详情用 <pre> 渲染原始内容，展示于模态弹窗；无 Markdown 渲染、无图表、无目录长报告（复盘类可达数千字）不可导航、不可快速定位，信息消费效率低；弹窗限制深度阅读
④ 无任务模型提交分析后仅弹一条 alert「已提交分析任务」，无进度、无阶段、无队列、无失败原因定位LLM 分析是分钟级异步任务，用户无从感知进度；失败后只能盲试
⑤ 对话上下文割裂聊天历史仅存于内存 chatLog，无会话持久化；无法在对话中引用报告或 @ 标的刷新即丢上下文；「针对某报告追问」只能复制粘贴，核心投研闭环断裂
⑥ 无引导与空状态无报告时仅一行「暂无报告」；无首次使用引导、无示例问题、无快捷入口新用户面对配置表单无从下手；功能发现成本高
⑦ 状态反馈单一仅 alert 文案 + 按钮 loading；无骨架屏、无进度条、错误无恢复路径弱网/慢模型场景下体验停滞感明显
⑧ 移动端弱对话/报告仅 lg 断点分栏；配置区 flex 换行；无移动端专项布局与手势窄屏下内容堆叠、操作区拥挤，移动查阅报告不可用
诊断结论：现有实现功能完整（对话、生成、模型管理均已打通），问题集中在「信息组织方式」与「内容呈现深度」——属于结构性与体验性问题，不涉及功能缺失。这决定了重构策略是「重新组织 + 升级呈现」而非推倒重来，后端 API 与既有组件体系可全部复用。

2. 信息架构重构

按「任务 → 报告 → 对话 → 配置」的认知层级，将原单页拆分为 5 个页面。入口收敛、职责单一、层级清晰。

2.1 架构总览

⌂ 投研工作台 /ai
  • 服务状态（常驻、轻量）
  • 快捷入口：生成复盘 / 继续上次分析 / 追问热点
  • 最近报告（Top 5）
  • 今日洞察：AI 摘要卡
  • 运行中任务实时预览
◈ 分析师 /ai/analyst
  • 会话列表（持久化、分组）
  • 对话流（Markdown 渲染）
  • 上下文面板：@标的 / 引用报告
  • 快捷指令：/复盘 /解读 /筛选
▤ 研究报告 /ai/reports
  • 报告列表（筛选/搜索/批量）
  • 报告阅读器（全屏、目录）
  • 结论摘要卡 + 数据图表
  • 导出 / 分享 / 追问
⇅ 任务中心 /ai/tasks
  • 任务队列（排队/运行/完成/失败）
  • 分阶段进度（采集→映射→成文）
  • 取消 / 重试 / 批量重试
  • 执行日志
⚙ 设置 /ai/settings
  • 模型管理（Provider CRUD）
  • Prompt 配置（5 个模板）
  • 分析默认值（范围/窗口/焦点）
  • 数据与通知

图 2-1 · 五区结构。加粗边框为高频使用区（工作台为入口，分析师与报告为核心工作区），任务与设置为支撑区。

2.2 导航结构

页面级导航（Sidebar）

  • 侧边栏「投研分析」组内：仪表盘 → 保留；AI 投研 → 改为可展开子菜单（工作台 / 分析师 / 研究报告 / 任务中心）；设置移出导航主链路（入口放工作台卡片内）。
  • 子菜单命中态：/ai/* 前缀高亮「AI 投研」父级，避免五页平铺挤压侧边栏。
  • 「自选收藏」保持独立，与投研模块互链（报告/对话可一键加入自选）。

页内导航（三级）

  • 工作台：顶部页头 + 卡片分区，滚动锚点。
  • 分析师：左会话列表（可折叠）+ 中对话 + 右上下文（可折叠）——三栏，桌面默认展开中栏。
  • 报告：列表视图 ↔ 阅读器视图切换；阅读器内左侧目录锚点。
  • 任务/设置：列表 + 详情、左侧设置分节导航。

2.3 内容优先级

优先级内容理由
P0 核心生成任务入口、报告阅读、对话追问用户完成「分析—阅读—追问」闭环的主路径
P1 支撑任务进度、上下文面板、最近报告异步场景的状态安全感与记忆辅助
P2 配置模型管理、Prompt 编辑低频且面向高级用户，独立成页、入口下沉
P3 装饰今日洞察摘要、状态详情增强体验，不阻塞主流程

4. 视觉与 UI 设计规范

在现有 v3.0 设计系统（tokens.css）之上做增量扩展，不推翻既有令牌体系，仅新增 AI 投研专属组件令牌与图表规范。

4.1 色彩语义扩展

品牌/功能色（沿用）

  • 主色 #2f7d5b / 浅 #4f9e76 / 深 #1d4e39
  • 品牌底纹 #eaf4ef（摘要卡、激活态）
  • 风险/警告 #d97706（Prompt 高级区、超时提示）

市场语义色（沿用）

  • 涨/利好 #e5484d 红，跌/利空 #12a150 绿
  • 仅用于行情数据（价格、涨跌幅、资金流向）
  • AI 定性判断（多空倾向/置信度）用品牌色表达，避免语义混淆

AI 结论语义（新增）

  • 偏多：品牌绿系 #2f7d5b；偏空：#d97706（琥珀，区别于行情红绿）
  • 置信度刻度：低 <50% / 中 50–75% / 高 >75%，对应中性/琥珀/品牌色
  • 证据标注一律 #9ca3af 灰，注明「AI 生成，仅供参考」

关键决策：引入轻量 Markdown 渲染器（如 marked + 白名单 sanitize，或后端渲染）而非直接输出 HTML——风险是 XSS 与样式失控，故必须：① 服务端或构建期渲染；② 只允许白名单标签；③ 表格/标题/列表/引用四类语法优先支持，满足复盘报告 95% 的格式需求。

场景方案说明

6.2 错误状态

错误类型呈现恢复动作
模型未配置/Key 失效工作台顶部横幅 + 状态点变红「去配置」直达设置页（引导流程 D）

6.3 空状态

无会话

插画 + 3 个示例问题（「帮我复盘今日行情」「解读宁德时代财报」「筛选半导体异动」），点击即发送——用示例降低空页恐惧。

无报告

「还没有研究报告」+ 主按钮「生成第一份复盘」+ 说明生成耗时约 1 分钟。

任务无记录

「暂无任务」+ 历史自动归档提示（超过 30 天自动清理）。

统一原则：每个空状态必须回答三问——「这里是什么、为什么为空、下一步做什么」，且至少要有一个可点击的动作，绝不出现「暂无数据」四字了事。

8. 设计依据与权衡说明

对每个核心决策给出依据与取舍，便于评审时逐条质询。

决策设计依据权衡 / 备选
五页拆分（工作台/分析师/报告/任务/设置）对应五个独立的心智任务：入口决策、交互对话、内容消费、异步跟踪、系统配置。符合「任务导向 IA」原则；每页职责单一，便于后续独立迭代与按需懒加载。备选：维持单页 + 锚点分区——缺点已由现状证明（滚动过长、配置干扰）。拆分代价是路由与状态管理成本增加，但可复用现有组件，净收益为正。
对话三栏布局投研对话的核心障碍是「AI 引用的标的是哪个、基于什么数据」——上下文面板把隐式上下文显性化，符合工作记忆外化原则（cognitive offloading）；会话列表支持多线程并行研究。备选：单栏 + 气泡内引用卡片——移动端采用；桌面保留三栏，因多屏工作流（对照行情看对话）是量化用户高频习惯。右栏默认折叠以减少干扰，按需展开。
报告结构化渲染（非纯文本）复盘报告信息密度高（多指数/板块/涨跌停），纯文本阅读耗时约 3–5 分钟；摘要卡 + 表格 + 图表将「定位关键信息」压缩到 10–30 秒，符合投研信息消费的扫描式阅读习惯。风险：结构化渲染可能丢失原文细节——通过「原文段落」与「结构化区块」双模式切换（阅读器右上角）兜底；Markdown 渲染安全风险见 4.2 callout。
任务模型 + 阶段进度LLM 分析是 30–90 秒的异步过程，心理学上「明确剩余步骤」比「百分比」更能降低等待焦虑（progress certainty 效应）；失败定位到阶段可指导用户自救（如换模型/扩窗口）。代价：后端需暴露任务状态与阶段字段（现有 task_id 已有基础，扩展即可）；若后端暂不支持，前端可先用「乐观进度 + 轮询完成」降级。
设置独立成页 + Prompt 高级折叠Prompt 工程是 1% 用户的诉求，若与日常功能同层，则 99% 用户被无关复杂度打扰；设置页同时满足「想折腾的人能找到」，符合 progressive disclosure（渐进披露）。风险：高级用户入口变深——通过工作台「⚙」卡片入口 + 命令面板跳转补偿，两步可达，可接受。
红涨绿跌与 AI 结论色分离行情数据遵循中国市场惯例（红涨绿跌）；AI 定性结论（多空/置信度）若沿用红绿会与行情混淆，故用品牌绿/琥珀——避免「AI 判断」被误读为「市场事实」。备选：AI 结论也用红绿——省一套色但语义污染，否决。
移动端底部 Tab + 单栏移动端核心场景是「查报告、看进度、随手追问」，三栏在 375px 不可用；底部 Tab 符合单手操作惯例，报告阅读在移动端以摘要卡 + 表格卡片化保证可读性。权衡：移动端不做「生成任务的高级参数调整」（保留默认值 + 焦点输入），重操作引导回桌面——符合移动优先内容消费的定位。
空状态三问原则空状态是产品首次体验的「第一次见面」，引导动作直接决定转化；提供示例问题同时承担了「功能演示」作用，降低 LLM 产品常见的「不知道该问什么」门槛。成本：需要维护示例文案与插画资源，收益远大于成本。

9. 渐进式实施路线图

4 个阶段，每阶段独立可发布、可回滚、可验收。先拆结构（低风险高收益），再升级呈现（核心体验），后增强交互（锦上添花）。

Phase 0 · 结构拆分（约 1 周）
只做路由与组件搬迁，零功能改动
  • /ai 拆为工作台；/ai/analyst、/ai/reports、/ai/tasks、/ai/settings 四个子路由，原功能原样迁入对应页
  • Sidebar「AI 投研」改可展开子菜单；工作台组装已有卡片
  • 验收：五个路由均可访问，原对话/生成/模型管理功能回归通过
Phase 1 · 报告阅读升级（约 1–1.5 周）
核心价值跃升：纯文本 → 结构化阅读
  • 引入 Markdown 安全渲染（marked + sanitize / 后端渲染），报告详情从弹窗迁移到全屏阅读器路由
  • 摘要卡提取（先按规则截取「摘要」章节，后续接入 LLM 提炼）、表格样式、目录锚点
  • ECharts 图表接入：先实现「指数走势」「板块涨跌」两个高频图表（数据来自现有行情接口）
  • 验收：打开历史报告即可见结构化视图；新旧报告均兼容；阅读器深色模式通过
Phase 2 · 分析师工作区（约 2 周）
对话升级为完整研究工作台
  • 会话持久化（后端新增会话表 + CRUD；chatLog 迁移）
  • 三栏布局：会话列表 + 对话 + 上下文面板；@ 标的解析（复用现有标的代码表）+ 引用报告（携带 report_id 与章节）
  • 输入区指令胶囊 + 示例问题空状态；回答支持 Markdown 渲染
  • 验收：多会话并行、@ 标的候选确认、引用报告回链三项通过
Phase 3 · 任务体系与效率增强（约 2 周）
异步可见性 + 高级效率
  • 任务中心：状态字段（排队/运行/完成/失败）+ 阶段进度 + 日志 + 重试/批量重试；工作台进度条与报告列表状态联动
  • 状态体系铺开：骨架屏、错误恢复、空状态三问、断网横幅
  • 快捷键 + 命令面板 + 首次配置向导 + 批量操作
  • 验收：全场景状态走查表逐项通过；新手路径（无模型→配置→首份报告）完整可走
Phase 4 · 移动端与打磨（持续）
作为横切优化随各阶段同步进行，专项收尾
  • 底部 Tab、单栏对话、上下文浮层、表格卡片化
  • 图表交互打磨（联动高亮、点击跳转）、动效与无障碍（prefers-reduced-motion、键盘可达性、ARIA）
  • 数据埋点：入口转化、任务成功率、报告阅读时长——指导后续迭代
风险预案：① 后端任务阶段字段若短期不可扩展 → Phase 3 拆出，先用「乐观进度 + 轮询」；② Markdown 渲染若存在安全顾虑 → 先做后端渲染或降级为受限渲染器；③ 会话持久化涉及后端新表 → 与现有 news_monitor.db 迁移并行，不影响前序阶段发布。
